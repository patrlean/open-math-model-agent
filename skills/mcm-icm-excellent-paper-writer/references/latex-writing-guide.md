# LaTeX 成稿与修订协议

在第一次调用 `write_paper` 前完整执行本协议。它约束的是如何把已经完成的模型、结果和图表稳定地写入 LaTeX，而不是替代建模与论文内容要求。

## 1. 先冻结事实，再生成全文

1. 确认所有小问已有结果文件、图表和验证结论；不要一边猜数值一边写论文。
2. 建立一次性的成稿清单：章节顺序、每节论点、符号表、结果键、图文件、表格、公式标签和引用。
3. 所有计算结果，包括 Summary 中的数字，都通过 `\VAR{results['file']['key']}` 引用。不要凭记忆重新键入数值。
4. 在正文使用结果前，先用 `results_get` 确认键存在、单位正确、精度合适。
5. `sections` 是可变长度的正文一级章节数组。章节数量和 `heading` 名称根据 tasks、模型叙事与论证结构自行决定；每个数组项恰好生成一个 `\section`。标题可以是 `Differential Equation Framework`、`Network Intervention Model` 等模型自定义名称，不要求使用 `Problem 1 Model`。`heading` 不得手写章节号；对应 `body` 内只按需要写 `\subsection` 或 `\subsubsection`，不得再写 `\section`。
6. 附录放入可变长度的 `appendices` 数组，参考文献放入 `references` 数组。不得在任何 section body 中手写 `\appendix`、`thebibliography` 或 `\bibitem`。MCM/ICM 模板固定按“main paper → appendices → references”的顺序渲染，References 始终位于最后。

## 2. 区分三层转义

必须区分“JSON 字符串”“LaTeX 源码”和“排版后的 PDF”：

- 期望进入 `.tex` 的 LaTeX 命令只有一个反斜杠，例如 `\subsection{Method}`。
- 在工具调用的 JSON 字符串中，这个反斜杠必须编码成 `\\subsection{Method}`。
- 表格换行在 `.tex` 中是 `\\`，在 JSON 字符串中必须编码为 `\\\\`。
- 不要因为 JSON 需要转义，就让最终 `.tex` 出现重复的语义反斜杠。
- 工具参数必须直接符合 schema；不要额外套一层 `arguments`，也不要把整个参数对象当成字符串。

若工具返回 `arguments not valid JSON` 或 `Invalid \\escape`，只修复 JSON 转义，不要重写论文内容。

## 3. 文本模式与数学模式

### 3.1 文本模式特殊字符

普通文字中的以下字符必须处理：

| 想显示的字符 | LaTeX 写法 |
|---|---|
| `%` | `\%` |
| `_` | `\_` |
| `&` | `\&` |
| `#` | `\#` |
| `$` | `\$` |

裸 `%` 会注释掉该行剩余内容；裸 `_` 和 `^` 常导致 `Missing $ inserted`。文件名、场景名和参数名中的下划线要么转义，要么放入安全的等宽文本命令中。

### 3.2 数学表达

1. 下标、上标、希腊字母、分式和数学运算符必须位于数学模式中。
2. 行内公式优先使用 `\(...\)`，减少裸 `$` 配对错误。
3. 一个逻辑公式使用一对完整的数学分隔符，不要在数值替换前后反复开关数学模式。

推荐：

```latex
\(R^2=\VAR{results['fit']['r2_full']}\), compared with
\(\VAR{results['fit']['r2_base']}\).
```

禁止：

```latex
($R^2=\VAR{results['fit']['r2_full']}$ vs
\VAR{results['fit']['r2_base']}$)
```

后一种写法容易留下孤立的 `$`，使后续整段误入数学模式。

### 3.3 Summary Sheet

Summary 中尽量用可读的文字描述复杂公式；确需符号时仍要完整进入数学模式。不要在文本模式直接写 `P_ext`、`R^2` 或 `e^{-x}`。

第一次提交前，用 `run_code` 对最终版本进行精确英文词数统计。MCM/ICM Summary 必须至少满足当前 Skill 的 450 词下限，优先控制在约 450–480 词并实际编译校准；不要声称“约 600 词”却不计数，也不要一次增加上百词去猜页面容量。

### 3.4 正文段落与列表结构

1. 一个自然段只承载一个主要表达单元。论述对象、小问、假设、步骤、结论或比较对象发生变化时，另起自然段或列表项；用于解释同一论点的理由、证据和影响保留在该段内，避免拆成大量单句碎段。
2. Problem requirements 中的每个小问必须是独立自然段或 `enumerate` 条目。不得把“Problem 1”“Problem 2”“Problem 3”等标签仅用源码换行连续写在同一个 LaTeX 段落中。
3. Model assumptions 中的每条假设必须是独立自然段或 `enumerate` 条目，并在该单元内说明假设内容、依据、简化作用和潜在误差。若有 8 条假设，应形成 8 个清晰可辨的段落或条目，而不是一个连续大段。
4. 同层级、可编号的内容优先使用 `enumerate`；无先后关系的短项可使用 `itemize`。每个 `\item` 可以包含多句完整解释，不要把多个逻辑项塞入同一个 `\item`。
5. LaTeX 源码中的普通换行不会产生新段落。正文分段必须使用空行或列表环境；不要用 `\\` 强行制造正文段间距，`\\` 仅用于表格换行或确有排版语义的场景。
6. 写完每个章节后检查视觉节奏：不得出现由多个带编号标签的独立事项拼成的一整块文字，也不要为了“多分段”而把同一论证链切碎。

## 4. 使用模板支持的安全 LaTeX

加载本 Skill 后，`write_paper` 自动使用 MCM/ICM 模板，不需要也不得自行改选通用或国赛模板。该模板已经提供 `amsmath`、`amssymb`、`graphicx`、`booktabs`、`geometry` 和 `hyperref`。正文可以安全使用这些包提供的常见命令，例如 `equation`、`align`、`cases`、`\eqref`、`\includegraphics` 和 `booktabs` 表格。

模板只固定 Summary 页、排版环境和文档区域顺序，不固定 task 数量、模型名称或目录标题。Agent 应根据英文论文叙事自行命名章节，Schema 不要求 `Problem 1/2/3` 式标题。

不要在章节正文中写 `\documentclass`、`\usepackage`、页边距设置、标题元数据或显式分页命令。不要假设 `algorithmic`、`subcaption`、`tikz`、`longtable` 等额外环境可用；若模板未声明支持，改用普通 `enumerate`、`tabular`、`minipage` 或现有图像。

## 5. 图、表、公式与引用

1. 每个 `\begin{...}` 都必须有同名的 `\end{...}`，每组花括号必须配平。
2. 表格每一行的单元格数必须与列格式一致；正文中的 `&` 必须转义，表格行末使用正确的 `\\`。
3. 标签使用唯一前缀：`eq:`、`fig:`、`tab:`；每个 `\ref` 或 `\eqref` 都必须有对应 `\label`。
4. 图片只引用确实存在的 `figures/*.png`，图内文字保持英文。
5. 单图通常使用 `0.6–0.8\textwidth`；双图并排时每张约 `0.45\textwidth`。不要为了凑页数随意放大图片。
6. `Overfull \\hbox` 是警告，不等于编译失败；只有明显影响可读性时再局部修复。

## 6. 第一次 `write_paper` 前的静态检查

逐项确认：

- Summary 的实际词数达到下限但仍有一页内排版余量；
- 没有文本模式下的裸 `_`、`^`、`%`、`&` 或孤立 `$`；
- 数学分隔符、花括号和环境成对；
- 每个 `\VAR` 路径真实存在；
- 表格列数一致；
- 标签唯一且引用可解析；
- 标题没有手工编号；
- 每个正文一级章节都是独立的 `sections` 数组项，未把全文塞入一个临时标题；
- `appendices` 只包含附录，`references` 只包含参考文献，References 位于最后；
- 没有使用模板未提供的环境；
- Problem requirements 中的每个小问均为独立段落或列表项；
- Model assumptions 中的每条假设均为独立段落或列表项；
- 没有仅靠源码换行拼接多个编号事项的连续大段；
- 每个结论都能追溯到结果或文献。

第一次 `write_paper` 应生成完整、结构稳定的论文。不要为了试探模板先提交半篇论文，也不要在调用前后凭记忆反复重抄 60k 以上的正文。

## 7. 按错误类型修复

读取工具返回值后只处理它明确指出的问题：

### 7.1 参数 JSON 错误

修复反斜杠和字符串边界；正文内容保持不变。

### 7.2 渲染错误

检查 `\VAR` 的文件名、键路径和数据类型。先用 `results_get` 找到真实结构，不要猜键名。

### 7.3 LaTeX 编译错误

根据错误行和错误类型做词法排查：

- `Missing $ inserted`：优先找文本模式中的 `_`、`^`、数学命令或不成对的 `$`；
- `Undefined control sequence`：检查拼写和模板是否提供该命令；
- `Extra alignment tab`：检查表格列数和 `&`；
- `Runaway argument` / `File ended while scanning`：检查花括号和环境是否闭合；
- `File not found`：检查图片路径和文件名。

一次只修复已定位的语法缺陷。不要围绕包支持、模板行号或其他无证据猜测写长篇 reasoning，也不要通过多次全文重写做盲目二分。

### 7.4 PAPER ACCEPTANCE FAILED

指标行用于说明当前状态；只有随后以项目符号列出的内容才是失败项。不要自己发明更严格的阈值。例如 `abstract_fill=83%` 若没有被列入失败项，就不要擅自按 90% 修订。

首次成功编译后，所有局部问题都先 `inspect_paper_blocks`，再使用 `edit_paragraph`。短摘要、某节分析不足、单个公式错误或验证意见都不是再次调用 `write_paper` 的理由。

## 8. 摘要局部修订

1. 先读取抽象块的完整内容和 `content_hash`。
2. 精确计算当前词数和缺口。
3. 只增加满足下限所需的实质内容，并留少量余量；不要从 388 词直接跳到 540 词。
4. 若 `first_section_page` 从 2 变为 3，说明摘要溢出；接受回滚，缩短后再提交。
5. 不通过调字号、页边距或显式分页绕过摘要规则。

## 9. 停止条件

当工具返回 `paper acceptance PASSED` 时，立即停止为了页数、摘要密度或“更接近目标页数”而继续修改。目标页数是写作方向，accepted range 才是验收边界；24 页已经处于 24–25 页范围时，不得仅为凑到 25 页添加新分析或重排版。

通过后只允许修复新发现的事实错误、题意遗漏、验证意见或用户明确要求；随后进入独立验证，不再进行无目标润色。
